# US103 - Synchronized flight simulation

## 1. Análise

### User Story

As a Flight Control Operator, I want to synchronize flight simulations step by step.

### Critérios de aceitação tratados

1. O componente é implementado em C.
2. A simulação usa processos, pipes e sinais.
3. É criado um processo por voo.
4. Cada processo de voo executa o respetivo plano de voo.
5. Cada processo de voo comunica com o processo principal por pipe.
6. O processo principal acompanha as posições das aeronaves ao longo do tempo através de uma estrutura de histórico.
7. A simulação avança de forma sincronizada por time steps.
8. Cada processo de voo envia uma atualização por step e aguarda autorização do processo principal antes de continuar.
9. O processo principal apenas avança a simulação depois de receber os updates de todos os voos ativos.
10. Os parâmetros obrigatórios da simulação são validados (time range, área, voos, weather, safety thresholds e performance settings).

## 2. Desenho


### Processo principal

Responsabilidades:

- validar parâmetros da simulação;
- criar um pipe por voo;
- criar um processo filho por voo com `fork()`;
- enviar `SIGUSR1` para iniciar os voos;
- receber `PositionUpdate` através dos pipes;
- guardar as posições num histórico dinâmico por voo;
- sincronizar os processos de voo por time step;
- libertar o próximo passo escrevendo o carácter `'N'` no `sync_pipe` de cada filho (implementação por pipe conforme o código; uso de `SIGUSR2` está comentado no código fonte);
- terminar os processos com `SIGTERM` em caso de interrupção;
- gerar um relatório simples no final.


### Processo de voo

Responsabilidades:

- carregar o plano de voo;
- aguardar `SIGUSR1` antes de iniciar;
- percorrer os segmentos do plano;
- interpolar posições entre o ponto inicial e final de cada segmento;
- enviar atualizações ao processo principal através do pipe;
- aguardar um comando no `sync_pipe` (leitura de um `char`) antes de avançar para o próximo time step; se o comando for `'N'` continua, caso contrário termina.
- tratar `SIGTERM`/`SIGINT` para terminar de forma controlada.

## 3. Estruturas principais

- `SimulationConfig`: parâmetros da simulação.
- `FlightPlan`: representação interna simples do plano de voo.
- `Segment`: segmento entre duas posições.
- `PositionUpdate`: mensagem enviada pelo processo de voo.
- `FlightRuntime`: estado mantido pelo processo principal para cada voo.
- `HistoryEntry`: posição guardada no histórico.

## 4. Sincronização

A sincronização da simulação, conforme implementada no código, usa uma combinação de sinal de arranque e pipes de sincronização:

- `SIGUSR1` é utilizado para iniciar todos os processos de voo de forma sincronizada;
- para avançar cada time step o processo principal escreve o carácter `'N'` no `sync_pipe` associado a cada filho; os filhos fazem uma leitura bloqueante desse pipe e só progridem quando recebem `'N'`;
- cada processo filho envia apenas um `PositionUpdate` por ciclo de execução;
- o processo principal utiliza `poll()` para esperar pelos updates de todos os voos ativos antes de libertar o passo seguinte.

Esta abordagem garante que a simulação evolui de forma coordenada e determinística, e corresponde ao código em `src/main.c` e `src/flight_process.c`.

## 5. Limitações assumidas

Esta implementação não trata a deteção de conflitos entre aeronaves, pois isso pertence à US102. A simulação usa interpolação linear entre segmentos para garantir uma base funcional e alinhada com a US103.
