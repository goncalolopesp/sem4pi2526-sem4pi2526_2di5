# US105 - Parallel simulation coordination using shared memory and synchronization primitives

## 1. Objetivo

Adicionar mecanismos avançados de concorrência ao simulador existente, permitindo coordenação entre múltiplos processos através de memória partilhada e sincronização explícita.

---

## 2. Requisitos Implementados

A implementação inclui:

- processo pai multithreaded;
- um processo filho por voo;
- memória partilhada POSIX;
- semáforos POSIX;
- mutexes pthread;
- condition variables pthread;
- sinais POSIX;
- suporte concorrente para múltiplos voos.

---

## 3. Arquitetura

### Processo Pai

Responsabilidades:

- criar memória partilhada;
- criar thread de monitorização;
- criar processos filho;
- coordenar sincronização;
- recolher updates.

### Thread de Monitorização

Responsabilidades:

- observar estado global da memória partilhada;
- aguardar notificações através de condition variables;
- imprimir estado global da simulação.

### Processos Filho

Responsabilidades:

- executar o voo;
- atualizar shared memory;
- notificar alterações.

---

## 4. Estruturas Introduzidas

### SharedSimulationState

Contém:

- array de estados partilhados;
- contador de updates;
- semáforos;
- mutex;
- condition variable;
- número de voos ativos.

### SharedFlightState

Contém:

- identificador;
- PID;
- posição;
- timestep;
- estado.

---

## 5. Modelo de Sincronização

| Mecanismo     | Utilização                        |
| ------------- | --------------------------------- |
| shared memory | partilha de estado                |
| semáforos     | exclusão mútua simples            |
| pthread mutex | proteção adicional                |
| pthread cond  | notificação entre threads         |
| sinais        | controlo do ciclo de vida         |
| pipes         | compatibilidade com US anteriores |

---

## 6. Compatibilidade

A US105 foi integrada mantendo:

- US100;
- US101;
- US102;
- US103.

Não foram removidos pipes nem sinais existentes.

Foi adicionada uma camada adicional de sincronização.

---

## 7. Testes Executados

### Um voo

Resultado esperado:

- active=1;
- updates incrementais.

### Dois voos concorrentes

Resultado esperado:

- active=2;
- updates partilhados;
- múltiplos PIDs.

Resultado observado:

- 2 processos ativos;
- 26 updates partilhados;
- tracker funcional;
- relatório final gerado;
- simulação terminada com sucesso.

---

## 8. Resultado

A implementação permite coordenação concorrente utilizando memória partilhada e sincronização explícita, mantendo compatibilidade com as user stories anteriores.
